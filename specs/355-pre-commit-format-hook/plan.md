## 3. `scripts/pre-commit.mjs` design

Shape mirrors `scripts/node-types-alignment.mjs`: pure functions exported for tests, an I/O shell
that runs only when executed as the entry point.

### 3.1 Staged paths
`git diff --cached --name-only --diff-filter=ACMR -z` (spawned without a shell), split on `\0`.
`-z` avoids `core.quotepath` escaping and handles spaces. Paths stay repo-relative with forward
slashes on every platform (memory: source-scanning tests need slash normalising). Run from
`git rev-parse --show-toplevel` — correct in a worktree, where `.git` is a file.

### 3.2 Classification (pure)
`classify(paths) → { csharp: string[], prettier: string[] }`.
- `csharp`: `*.cs`.
- `prettier`: `matchesFormatScope(path)` — the `format:check` globs (spec FR-004). Implemented with
  a small explicit matcher (top dir in {`apps`,`e2e`} and extension in the list, or path ===
  `playwright.config.ts`), not `path.matchesGlob` (experimental on Node 22).
- **Drift guard (FR-012)**: exported constant `FORMAT_CHECK_SCOPE` holds the glob strings; a test
  asserts they appear verbatim in `package.json`'s `scripts["format:check"]`.

### 3.3 C# leg
- `owningProject(path, exists)` (pure, `exists` injected): walk parent directories up to the repo
  root, return the first directory containing exactly one `*.csproj` (directory listing injected
  too). None → skipped.
- `planDotnetFormat(csharpPaths, lookup) → Array<{ project, files }>`. If the number of distinct
  projects exceeds `SOLUTION_FALLBACK_PROJECT_COUNT` (initial value 3 — 4 projects × ~20 s exceeds
  the 73 s solution run; phase 4 re-measures and records the value's reason next to it), return one
  entry `{ project: 'SmartSentinelEye.slnx', files: all }`.
- `dotnetArgs({ project, files })` → `['format', project, '--verify-no-changes', '--no-restore',
  '--exclude-diagnostics', 'IDE1006', '--include', ...files]`. Chunk `files` so one command line
  stays under Windows' 32 767-char limit.
- Spawn `dotnet` (no shell), inherit stdout/stderr so dotnet's own diagnostics are the message.
  Exit 0 → pass; 2 → formatting failure; other → tool failure (FR-007).
- FR-008: `git diff --name-only -z` (unstaged) ∩ staged `.cs` → print the working-tree note.

### 3.4 Frontend leg (in-process, index content)
For each staged prettier path: `prettier.getFileInfo(path, { ignorePath: '.prettierignore' })` →
skip if `ignored`; content = `git show :<path>` (index blob; one spawn per file is acceptable for a
commit's file count — use `git cat-file --batch` only if phase 4 measures it matters);
`options = await prettier.resolveConfig(path)`; `await prettier.check(content, { ...options,
filepath: path })`. False → failing file. This makes partial staging exact for this leg (spec §3).

### 3.5 Output and exit
Collect failures from both legs (run both even if the first fails, so one commit attempt shows
everything). Print per leg: failing files, fix command, and one line: `Skip once with git commit
--no-verify; CI's format gates still apply (ADR-0033).` Exit 1 on any failure.

### 3.6 Install behaviour (verified facts, re-verify in phase 4)
- Husky 9.1.7 `husky` command: returns early for `HUSKY=0`, when `.git` is absent (Docker contexts,
  tarballs) — exit 0 in both; otherwise `git config core.hooksPath .husky/_` and writes
  `.husky/_/` (self-gitignored).
- `core.hooksPath` is written to the **common** config, so it applies to every worktree; a relative
  hooksPath resolves against each worktree's top level. A worktree that never ran `pnpm install`
  has no `.husky/_/` → git finds no hook → commits proceed unchecked (same as today; documented).
  Phase 4 verifies by `git worktree add` in the scratch dir.
- pnpm 10 runs the **root project's** own `prepare` (its build-script allowlist covers
  dependencies, not the root). CI `pnpm install --frozen-lockfile` therefore runs `husky`, which
  sets hooksPath in the runner's checkout — inert, no workflow commits. No `HUSKY=0` added to CI
  (FR-010: no new CI behaviour).
- GUI clients (Rider, Visual Studio) run hooks through Git for Windows' `sh`; `node`/`dotnet`
  must be on that PATH. Husky v9 sources `~/.config/husky/init.sh` for PATH fixes — documented in
  CONTRIBUTING, not scripted.

## 4. Invariants

- The hook never writes to the working tree or the index (asserted by tests: `git status
  --porcelain` and `git diff` identical before/after).
- The hook's verdict is a subset of CI's: anything it rejects, CI rejects (same flags, same
  prettier config/ignore/scope).
- No path outside the staged ACMR set is checked.

## 5. Tests (Phase 4a, RED) — `scripts/pre-commit.test.mjs`

Run by `pnpm test:guards` (and so by `pnpm test` in CI's `frontend` job, ubuntu, no Docker, no
.NET). **No shard-filter entry is needed**: `tests/Integration.Tests/ci-shards/*.filter` select
xUnit classes only; `node --test` files are collected by the glob.

Fixture pattern copied from `scripts/create-new-feature.test.mjs`: `mkdtempSync` throwaway repos,
`spawnSync('git', …)` with `-c user.name/-c user.email`, cleanup in `after`. The fixture repo gets
a copy of `.prettierrc.json`, `.prettierignore` and a minimal `package.json` whose `format:check`
is the real one. The hook runs as `node <repo>/scripts/pre-commit.mjs` with `cwd` = fixture repo.
**Prettier resolution**: the script resolves `prettier` relative to its own file (`import`), so it
uses the real workspace's `node_modules` while operating on the fixture repo.

End-to-end (real git, real prettier):
1. clean staged `apps/a/x.ts` → exit 0.
2. mis-formatted staged `apps/a/x.ts` → exit ≠ 0 **and** stdout/stderr contains `apps/a/x.ts`
   **and** the fix command. (Asserting the file name, not just the exit code: a missing script also
   exits non-zero — `node` "Cannot find module" — so an exit-code-only assertion would pass red for
   the wrong reason.)
3. mis-formatted staged `docs/n.md` and `scripts/x.mjs` → exit 0.
4. staged clean, unstaged mis-formatted `apps/a/x.ts` → exit 0; working tree unchanged.
5. staged deletion + rename → exit 0.
6. nothing staged → exit 0 and `dotnet` not invoked (runner spy, see below).
7. the hook leaves `git status --porcelain` and file bytes unchanged in every case above.
8. `.prettierignore`d path under `apps/**/dist/` mis-formatted → exit 0.

Unit (pure functions; `dotnet` runner injected, never spawned in CI):
9. `classify` — `.cs` vs scope vs neither, including `playwright.config.ts`, `apps/x/y.yml`,
   `.github/workflows/ci.yml` (not in scope), backslash-free output.
10. `owningProject` — nearest ancestor wins; none → skipped; walk stops at repo root.
11. `planDotnetFormat` — grouping per project; fallback to the `.slnx` above the threshold.
12. `dotnetArgs` — exactly the CI flags (`--verify-no-changes`, `--no-restore`,
    `--exclude-diagnostics IDE1006`), project target, chunking under the length limit.
13. exit mapping — runner returns 2 → formatting failure message; 1 → tool-failure message; both
    block.
14. drift guard (FR-012) — `FORMAT_CHECK_SCOPE` globs appear in the real `package.json`
    `format:check`; a counterfactual fixture `package.json` with a changed glob fails.

**Red observation**: all of 1-14 fail before `scripts/pre-commit.mjs` exists (import error for
unit tests; missing file name in output for e2e). The test-writer quotes that output verbatim; the
assertion-level red for e2e #2 is the "does not contain `apps/a/x.ts`" failure.

**Real `dotnet format` is not exercised in CI** (the `frontend` runner has no .NET 10 SDK and the
fixture would need a restore). It is verified by counterfactual in Phase 5 (spec §4 step 3),
already demonstrated once in spec §1.1. Recorded as a known gap rather than hidden behind a skip.

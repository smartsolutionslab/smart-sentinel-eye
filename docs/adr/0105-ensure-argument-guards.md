# ADR-0105: Standardize argument guards on `Ensure.That`

**Status:** **Accepted**
**Date:** 2026-06-01
**Extends:** ADR-0059 (Ensure fluent validation)
**Supersedes:** —
**Superseded by:** —

## Context

ADR-0059 introduced the `Ensure.That(value).…` fluent chain for
validating **value-object invariants** (a `string` overload throwing
`ArgumentException` on the first failed predicate). It deliberately
covered only strings, because that was the only need at the time.

Separately, argument **null guards** were written the idiomatic .NET way
— `ArgumentNullException.ThrowIfNull(x)` — at ~277 call sites across
domain constructors, application handlers, API endpoints, repositories,
hosted services, and DI/EF extension methods. The result was two
different idioms for the same concept ("reject a bad argument at the
method boundary"): a hand-rolled `Ensure` chain for strings, and a BCL
helper for null. New code had to choose, and reviews had to police the
choice.

## Decision

**All argument-precondition guards use the `Ensure.That(...)` chain.**

- `Ensure.That(x).IsNotNull()` replaces
  `ArgumentNullException.ThrowIfNull(x)`. It throws
  **`ArgumentNullException`** (the same type `ThrowIfNull` raised) and
  captures the parameter name from the call site via
  `[CallerArgumentExpression]`, so the produced message is identical and
  no `catch`/test that depended on the type or message changes.
- The `string` overload continues to validate value-object invariants
  (`IsNotNullOrWhiteSpace`, `HasMinLength`, `Matches`, …), throwing
  `ArgumentException` as before. It also gains `IsNotNull()` for the
  null-only case.
- `Ensure` gains a generic reference overload
  (`That<T>(T) where T : class`) returning `EnsuredObject<T>`. The
  `string` overload is more specific, so string arguments still bind to
  the value-object chain.

### Scope and exclusions

In scope (converted): every `ArgumentNullException.ThrowIfNull` in
Domain, Application, Api, and Infrastructure — handlers, endpoints,
aggregates, repositories, DbContext `OnModelCreating`, DI/persistence
modules, broadcasters, hosted services.

**Out of scope (left as-is), by design:**

- **`AppHost`** — the Aspire composition root does not reference
  `Shared.Kernel` (no domain dependency by design), so `Ensure` is not
  available there. Its handful of guards stay on `ThrowIfNull`.
- **Generated EF migration files** (`**/Migrations/**`) — regenerated by
  tooling; never hand-edited.
- **Parse / format / deserialization failures** — e.g. the
  `RuleConfiguration` packed-string decoder's
  `throw new ArgumentException("Malformed packed RuleAction …")`. These
  are *data-format* errors, not argument-null/precondition guards;
  `Ensure` is not the right tool and they keep throwing
  `ArgumentException`/`FormatException`.
- **Value-range preconditions on primitives** (`int`, `double`, …).
  `Ensure` today guards reference types (`IsNotNull`) and string
  invariants. A value-type predicate API is not introduced
  speculatively; revisit if such guards proliferate.

## Consequences

**Positive:**

- One guard idiom across the codebase; no per-site style choice.
- Behaviour-preserving: `IsNotNull()` throws the same
  `ArgumentNullException` with the same parameter name, so existing
  tests and exception handlers are unaffected.
- `Ensure` is now the single, greppable validation surface.

**Negative:**

- `Ensure.That(x).IsNotNull()` is slightly longer than
  `ArgumentNullException.ThrowIfNull(x)`.
- Files that previously only used the BCL guard now take a
  `using SmartSentinelEye.Shared.Kernel;` dependency.

**Enforcement:** documentation-led for now (this ADR + CLAUDE.md). A
build-time ban via `Microsoft.CodeAnalysis.BannedApiAnalyzers`
(`ArgumentNullException.ThrowIfNull` on the banned list, AppHost +
migrations exempt) is a deferred follow-up to make regressions fail the
build.

## Alternatives Considered

**Keep `ArgumentNullException.ThrowIfNull` — REJECTED.** It is idiomatic
.NET and zero-alloc, but it left two idioms for one concept. The repo
already committed to the hand-written `Ensure` style (ADR-0059); one
idiom wins on consistency. `Ensure.NotNull(x)` keeps
`[CallerArgumentExpression]`, so ergonomics are not lost.

**Terse `Ensure.NotNull(x)` static helper — REJECTED** in favour of the
fluent `Ensure.That(x).IsNotNull()`, which keeps a single entry point
(`Ensure.That`) for both value-object invariants and argument guards and
chains naturally (`.AndReturn()` to bind the validated value).
